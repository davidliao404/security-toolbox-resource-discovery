# 大模型增强提示语模板设计

## 1. 定位

大模型增强是可选能力，不是默认路径。默认仍使用 `risk_rules.yml` 规则库生成风险线索、置信度和整改优先级。

当租户显式开启 `rules_plus_llm`，并由上层服务注入大模型增强器后，提示语模板用于约束模型只做三类辅助工作：

- 风险置信度增强。
- 管理者摘要增强。
- 整改建议增强。

当前仓库只提供模板渲染，不内置真实模型调用，不保存模型 API Key。

## 2. 输入边界

模板只接收最小化上下文：

- 风险线索 ID。
- 风险类别。
- 严重级别。
- 规则置信度。
- 端口。
- 服务类型。
- 哈希化资产标识。
- 模型供应商和模型名称。
- 是否允许网络搜索。
- 数据共享范围。

模板不得接收：

- 原始 FOFA 或中转站响应。
- 明文域名或 IP。
- 客户内部备注。
- SaaS API Key。
- 本地扫描或验证结果。

## 3. 模板类型

### 3.1 风险置信度增强

目标：

- 结合公开背景判断同类暴露是否应提高或降低复核优先级。
- 输出 `confidence_adjustment`，范围限制在 `-0.2` 到 `0.2`。
- 输出简短的 `external_context_summary`，供管理者报告引用。

禁止：

- 把被动线索描述为已确认漏洞。
- 输出攻击步骤。
- 编造客户资产归属。

### 3.2 管理者摘要增强

目标：

- 把技术线索改写成非技术管理者能理解的说明。
- 保留证据链。
- 明确需要本地验证。

禁止：

- 编造业务影响。
- 编造攻击事实。
- 用恐吓式措辞制造确定性结论。

### 3.3 整改建议增强

目标：

- 给出安全、可执行的本地验证或整改建议。
- 允许给出优先级调整建议，但不得覆盖规则证据。
- 建议责任角色，例如 IT 管理员、系统负责人、网络管理员。

禁止：

- 生成利用代码。
- 生成绕过认证方法。
- 生成弱口令尝试建议。
- 引导云端主动攻击验证。

## 4. 当前实现

代码位置：

- `src/resource_discovery/prompt_templates.py`

导出函数：

- `render_risk_confidence_prompt(context)`
- `render_manager_summary_prompt(context)`
- `render_remediation_prompt(context)`

测试位置：

- `tests/test_prompt_templates.py`

验证重点：

- 模板包含安全边界。
- 模板要求结构化 JSON 输出。
- 模板不包含明文目标。
- 模板保留“被动发现、需要本地验证”的产品边界。

## 5. 后续接入建议

真实模型连接器落地前，需要补齐：

- 租户级模型 API Key 的密钥管理。
- token 和费用估算。
- 调用超时与失败降级。
- 模型响应 JSON 校验。
- 审计事件，包括模型供应商、模型名称、数据共享范围、网络搜索开关和调用结果。

## 6. 已实现的响应防护

当前 `enrich_risk_hints` 已对模型增强结果做基础防护：

- 未知 `risk_hint_id` 会被忽略。
- `confidence_adjustment` 会被限制在 `-0.2` 到 `0.2`。
- `external_context_summary` 会截断到 200 字以内。
- 非列表类型的 `items` 会按空结果处理。
- 规则置信度不会被覆盖，只新增 `analysis_confidence`。
- 如果连接器返回 `usage`，会清洗并保留 `prompt_tokens`、`completion_tokens`、`total_tokens` 和 `estimated_cost_usd`。

启用大模型增强时，CLI 审计日志会额外写入 `llm_analysis_used` 事件，记录模型供应商、模型名称、网络搜索开关和数据共享范围。
如果存在 `usage`，该事件也会记录清洗后的 token 与费用估算。当前仓库只承载这些字段，不内置真实模型计费逻辑。
