# 资源发现模块后续 TODO

## 1. 双轨风险分析：规则库 + 轻量提示语 Agent

### 背景

当前 PoC 的风险线索、优先处置建议和整改优先级已迁移到 `risk_rules.yml`。在此基础上，继续保留一个更有价值的双轨方案：

```text
默认模式：YAML/JSON 规则库
客户显式同意：轻量提示语 Agent + 支持网络搜索的大模型
```

### 产品设想

当客户不愿使用第三方大模型分析结果时：

- 仅使用本地规则库。
- 不向第三方模型发送资产、域名、标题、组件或风险线索。
- 结果完全可离线、可审计、可解释。

当客户愿意使用第三方大模型增强分析时：

- 调用预设好的轻量提示语 Agent。
- 使用客户配置的大模型 API Key。
- 可选启用支持网络搜索的大模型能力。
- 对被动发现结果做二次分析，增强置信度、风险解释和处置建议。
- 输出新增字段，例如：
  - `llm_confidence_adjustment`
  - `external_context_summary`
  - `reasoning_evidence`
  - `model_used`
  - `search_enabled`
  - `data_shared_scope`

### 适合增强的维度

- 判断组件或产品是否已经过期。
- 判断暴露服务是否常见于高风险攻击面。
- 结合公开资料判断某类入口近期是否有高利用热度。
- 将技术线索改写为更适合管理者阅读的说明。
- 对相似风险进行合并和去重，减少报告噪声。
- 给出处置优先级调整建议。

### 安全与合规要求

- 必须由客户显式开启。
- 必须支持关闭网络搜索。
- 必须支持数据最小化模式，只发送必要字段：
  - 服务类型
  - 端口
  - 产品名
  - 版本
  - 标题摘要
  - 风险类别
  - 脱敏域名或哈希化资产标识
- 默认不发送完整原始响应。
- 默认不发送客户内部备注。
- 不发送 SaaS API Key、客户凭据或本地扫描结果。
- 记录审计日志：
  - 是否调用大模型
  - 模型供应商
  - 是否启用网络搜索
  - 发送字段范围
  - 返回时间
  - token/费用估算

### 建议架构

```text
Risk Hint Engine
-> Rule Analyzer
-> Optional LLM Risk Enricher
-> Confidence Merger
-> Report Builder
```

其中：

- `Rule Analyzer` 是默认路径，必须始终可用。
- `LLM Risk Enricher` 是可选增强路径，必须由租户配置显式开启。
- `Confidence Merger` 合并规则库结果和大模型增强结果，但不能让大模型直接覆盖确定性证据。

### 置信度合并原则

- 规则命中提供基础置信度。
- 多来源证据、端口命中、产品命中、标题命中可提高置信度。
- 大模型只能提供置信度调整建议，不能直接把被动线索升级为“已确认漏洞”。
- 报告中必须区分：
  - 规则判断
  - 大模型增强分析
  - 需要本地验证的结论

### 当前判断

这个方向值得进入后续设计。它能同时满足两类客户：

- 强合规客户：只用本地规则库。
- 愿意使用大模型增强的客户：获得更高质量的报告解释、置信度和处置建议。

关键约束是：大模型增强必须是显式开启的可选能力，且默认不上传敏感原始数据。
