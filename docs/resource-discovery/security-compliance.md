# 互联网暴露面资源发现模块安全与合规设计

## 1. 设计目标

安全与合规设计目标是确保资源发现网关在提供被动资产发现能力时，不扩大客户数据暴露面，不引入未授权探测风险，并能满足香港与内地客户的基础合规预期。

核心原则：

- 最小化收集。
- 区域隔离。
- 租户隔离。
- 全链路审计。
- 密钥集中管理。
- 禁止云端主动攻击验证。
- 报告结论可解释、可复核。

## 2. 租户隔离

要求：

- 所有任务、快照、审计日志和配额统计必须绑定 `tenant_id`。
- 不同租户之间不得共享发现结果。
- 租户级配置包括区域、供应商可用性、配额、数据留存策略和报告语言。
- 租户级分析配置必须明确是否启用第三方大模型、模型供应商、模型名称、网络搜索开关和数据共享范围。
- 管理后台跨租户查询必须具备单独权限和审计记录。

隔离边界：

- 应用层：每次请求强制校验租户。
- 数据层：所有数据表或集合包含租户字段。
- 密钥层：SaaS 凭据按区域和供应商隔离，不按客户明文暴露。
- 日志层：日志检索必须受权限控制。

## 3. API 鉴权

安全工具箱调用资源发现网关时必须具备：

- 客户端 ID。
- 租户 ID。
- 请求时间戳。
- 随机 nonce。
- 请求签名。

网关必须校验：

- 时间窗口，防止重放。
- 签名有效性。
- 客户端是否属于该租户。
- 客户端是否有该区域访问权限。
- 请求是否超过配额。

敏感接口必须记录审计日志。

## 4. 客户侧身份

网关不直接管理客户最终用户登录，但必须接收安全工具箱传递的操作者标识：

- `operator_id`
- `operator_role`
- `operator_display_name` 的脱敏摘要

用途：

- 审计任务创建人。
- 控制报告查看权限。
- 支持客户内部追责和复核。

网关不应保存客户侧完整账号资料。

## 5. SaaS 密钥管理

要求：

- FOFA 等 SaaS 密钥只能存放在云端密钥管理系统或等效安全配置中。
- 安全工具箱客户端不得保存 SaaS 密钥。
- 密钥按区域、供应商、环境隔离。
- 密钥轮换必须不影响已有任务状态查询。
- 日志和错误信息不得输出密钥、token 或签名串。

MVP 至少需要：

- 生产和测试密钥分离。
- 密钥访问审计。
- 调用失败时只返回供应商认证异常，不返回敏感原文。

## 6. 数据最小化

网关只收集完成任务所需的最小数据：

- 租户标识。
- 操作者脱敏标识。
- 输入种子。
- 任务目的。
- 查询计划。
- 归一化结果。
- 风险线索。
- 报告结构。
- 审计日志。

不应收集：

- 客户内部完整资产库。
- 客户员工个人资料。
- 未授权第三方目标。
- 本地扫描凭据。
- 本地漏洞验证结果中的敏感细节，除非后续版本有明确合规设计。

可选大模型增强的数据最小化：

- 默认关闭，不向第三方模型发送任何发现结果。
- 启用时必须由租户级配置显式声明 `llm_enabled=true`。
- 当前只允许 `data_sharing_level=minimal`，不得发送原始 SaaS 响应。
- 最小化上下文只包含风险类别、严重级别、规则置信度、端口、服务和哈希化资产标识。
- 不发送 SaaS API Key、客户凭据、本地扫描结果或客户内部备注。
- 网络搜索必须单独配置，不得跟随模型增强默认开启。

## 7. 日志脱敏

日志中允许记录：

- 租户 ID。
- 任务 ID。
- 来源 SaaS。
- 查询类型。
- 结果数量。
- 错误码。
- 配额消耗。

日志中禁止记录：

- SaaS 密钥。
- 完整认证头。
- 完整原始响应。
- 高敏感客户备注。
- 未脱敏个人信息。

输入种子日志建议：

- 域名可记录完整值。
- IP 段可记录完整值，但按租户权限保护。
- 组织名可记录脱敏摘要和必要显示值。
- 操作者显示名默认脱敏。

## 8. 数据留存

默认策略：网关保存短期任务快照与脱敏结果。

建议：

- 任务元数据：保留 180 天。
- 审计日志：保留 180 至 365 天，按客户合同调整。
- 归一化结果快照：默认 30 至 90 天。
- 原始 SaaS 响应：默认不长期保存。
- 报告结构：默认 30 至 90 天，完整报告可回存客户本地。

删除要求：

- 租户停用后按合同和合规要求删除或匿名化。
- 客户可请求删除任务快照。
- 删除操作必须保留必要审计记录。

## 9. 审计

必须审计：

- 创建任务。
- 取消任务。
- 重试任务。
- 查看报告。
- 导出技术附录。
- 管理后台查看租户数据。
- 修改供应商密钥。
- 修改配额和留存策略。
- 修改租户级大模型分析配置。
- 调用大模型增强分析。

审计字段：

- 时间。
- 租户。
- 操作者。
- 来源 IP 或客户端实例。
- 操作类型。
- 任务 ID。
- 结果。
- 错误码。
- 分析模式。
- 大模型供应商和模型名称。
- 网络搜索开关。
- 数据共享范围。

当启用大模型增强时，必须额外记录 `llm_analysis_used` 事件，字段包括：

- `provider`
- `model`
- `web_search_enabled`
- `data_sharing_level`

## 10. 合规边界

### 10.1 香港区域

香港区域面向香港非盈利和跨境敏感客户，重点关注：

- 个人资料最小化。
- 明确数据使用目的。
- 合理安全措施。
- 保留期限可解释。
- 向外部 SaaS 传递查询信息前进行客户提示。

默认策略：

- 网关部署在香港或客户认可区域。
- 快照和日志不复制到内地区域。
- 供应商配置和密钥独立。
- 报告中避免不必要个人资料。

### 10.2 内地区域

内地区域面向内地中小企业和非核心政府单位，重点关注：

- 个人信息处理合法、正当、必要。
- 数据出境边界。
- 重要数据和敏感数据识别。
- 网络安全等级保护相关安全控制。
- 政府单位或事业单位的额外采购和数据要求。

默认策略：

- 内地客户任务默认在内地区域执行。
- 内地区域优先配置内地可用的数据源。
- 对跨境 SaaS 调用进行显著提示和可配置禁用。
- 不将内地区域快照复制到香港区域。

### 10.3 双区域共同要求

- 区域间数据不自动同步。
- 区域间密钥不共享。
- 区域间管理操作必须审计。
- 客户合同中明确数据处理区域、供应商类别和留存策略。

## 11. 禁止能力

第一版禁止：

- 云端主动端口扫描。
- 云端漏洞验证。
- 云端弱口令验证。
- 云端目录爆破。
- 云端漏洞利用。
- 云端自动攻击链验证。
- 查询明显无授权的第三方目标。
- 对外提供攻击性搜索模板。

如果后续增加主动验证能力，必须作为独立合规模块重新评审。

## 12. 安全滥用防护

防护措施：

- 租户实名认证或合同绑定。
- 任务目的必填。
- 输入范围提示和授权确认。
- 单任务种子数量限制。
- 单租户每日配额限制。
- 异常查询频率告警。
- 高风险关键词查询限制。
- 管理后台可暂停租户。

可疑行为包括：

- 大量无关域名查询。
- 大范围公网 IP 段查询。
- 高频失败任务。
- 尝试绕过查询模板。
- 同一租户查询多个无关联组织。

## 13. 报告安全措辞

报告中不得把被动发现线索描述为已确认漏洞。

推荐措辞：

- “发现疑似互联网暴露的远程访问入口。”
- “建议优先复核该服务是否确属本组织并确认访问控制。”
- “该结论基于外部资产发现数据，需结合本地验证确认。”

避免措辞：

- “该系统已被攻破。”
- “该服务存在确定漏洞。”
- “可直接利用。”

## 14. 当前假设

- 网关默认保存短期快照和脱敏结果。
- 完整报告和处置记录优先回存客户本地。
- 双区域部署作为第一版架构原则。
- 内地区域和香港区域使用独立供应商配置。
