# 工具箱外部团队集成规则

## 1. 接口归属

资源发现网关团队拥有第一版接口定义权。外部工具箱团队必须适配以下文档中的接口、鉴权、状态、分页和错误模型：

- `docs/resource-discovery/toolbox-api-contract.md`
- `docs/resource-discovery/toolbox-handoff.md`

联调目标是确认工具箱实现是否正确调用当前网关协议，不是重新设计网关 API。

## 2. 冻结范围

以下内容在本轮生产上线准备中视为冻结：

- 路径前缀：`/api/v1/discovery`
- 四个接口：获取 scope profile、创建任务、查询任务状态、分页拉取结果
- HMAC-SHA256 签名字段和签名原文格式
- `queued`、`running`、`success`、`partial_success`、`failed`、`cancelled` 状态语义
- `assets`、`services`、`source_evidence` 分页结果结构
- 第一版错误对象和错误码
- 工具箱不得提交 FOFA 原生查询语句，只能提交结构化授权范围

## 3. 外部工具箱团队职责

- 按网关文档生成签名请求头，并确保每次请求使用新的 nonce。
- 在创建任务前获取 `scope-profile`，页面只允许用户缩小授权范围。
- 使用异步轮询处理任务，不把 `queued` 当成失败。
- 按 `result_type` 分页拉取结果，并将长期资产库存储在工具箱侧。
- 正确展示 `partial_success`、`freshness`、`ownership_confidence` 和供应商错误。
- 不保存 FOFA、uncover 或其他外部供应商密钥。
- 不把被动发现线索展示成漏洞确认、在线确认或资产下线确认。

## 4. 可接受反馈

外部团队可以提交以下反馈：

- 文档描述不清或示例不足。
- 当前实现与已冻结文档不一致。
- 签名样例、错误样例或分页样例需要补充。
- 发现网关实现缺陷或测试覆盖缺口。

反馈不自动改变接口协议。确需改变字段、路径、状态或错误码时，必须由网关负责人批准并形成版本化迁移说明。

## 5. 联调验收门槛

- 工具箱能获取租户授权范围并正确渲染可缩小范围。
- 越权范围被网关拒绝，工具箱不自动重试同一越权请求。
- 工具箱能创建任务、轮询到终态、分页拉取三类结果。
- 工具箱能处理 `partial_success` 并展示可恢复供应商错误。
- 工具箱日志、数据库和浏览器存储不包含外部供应商密钥。
- 工具箱实现不要求网关改变已冻结 API 才能完成第一版上线。
