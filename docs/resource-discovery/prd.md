# 互联网暴露面资源发现模块 PRD

## 1. 产品目标

互联网暴露面资源发现模块面向内部 IT 人员不足但安全要求较高的组织，帮助其快速获得管理者可读的互联网暴露面报告，并将高风险线索回流到私有化部署的“安全工具箱”中进行本地验证和处置。

第一版产品目标：

- 让管理者理解组织当前互联网暴露面规模和主要风险。
- 让 IT 管理员获得可操作的资产清单和处置优先级。
- 通过公有云资源发现网关统一接入 FOFA 等外部资产发现 SaaS。
- 保持云端能力边界清晰，只做被动发现、聚合、归一化和报告辅助。

## 2. 用户画像

### 2.1 管理者

典型角色：机构负责人、IT 负责人、行政管理者、安全负责人。

关注点：

- 我们暴露在互联网上的资产有多少。
- 哪些暴露项最危险。
- 是否存在远程访问入口、管理后台、测试环境、过期系统。
- 应优先投入多少资源处理。
- 报告是否可以用于内部汇报和整改跟踪。

### 2.2 IT 管理员

典型角色：网络管理员、系统管理员、兼职安全人员。

关注点：

- 资产是否归属本组织。
- 风险线索是否有证据。
- 如何把线索转为本地巡检、扫描或整改任务。
- 哪些结果可能是误报。
- 如何导出资产清单。

### 2.3 售前或安全服务人员

典型角色：产品售前、托管安全服务工程师、合作伙伴交付人员。

关注点：

- 能否快速生成客户可读报告。
- 能否解释风险来源和处置优先级。
- 能否避免高风险主动探测带来的合规问题。

## 3. 使用场景

### 3.1 首次暴露面盘点

客户输入组织名、主域名、IP 段等基础信息，系统生成首次互联网暴露面报告。

### 3.2 周期性安全汇报

客户按月或按季度执行发现任务，比较新增资产、新增开放端口和新增高风险线索。

### 3.3 重大活动前检查

客户在上线、审计、重大活动或外部检查前，快速了解当前暴露入口。

### 3.4 本地处置联动

客户将高风险暴露服务导入安全工具箱本地任务，进行漏洞验证、配置巡检或人工复核。

## 4. 核心用户旅程

1. IT 管理员在安全工具箱中进入“互联网暴露面发现”。
2. 选择组织或资产范围，输入组织名、根域名、IP 段等种子。
3. 系统显示任务范围、数据来源、预计消耗和合规提示。
4. IT 管理员提交任务。
5. 安全工具箱调用资源发现网关。
6. 网关通过 FOFA 连接器执行被动查询。
7. 网关归一化、去重、生成风险线索和报告草稿。
8. 安全工具箱展示管理者摘要和技术附录。
9. IT 管理员确认资产归属，创建本地验证或整改任务。
10. 管理者查看报告摘要和优先处置建议。

## 5. MVP 范围

MVP 必须包含：

- 创建发现任务。
- 支持组织名、根域名、IP 段作为输入种子。
- FOFA 查询规划和调用。
- 资产、暴露服务和风险线索归一化。
- 简单去重和置信度标注。
- 管理者报告摘要。
- 技术附录资产清单。
- 任务状态查询。
- 失败原因展示。
- 审计日志。
- 短期任务快照。

## 6. 非目标

第一版明确不做：

- 云端主动端口扫描。
- 云端漏洞验证。
- 云端弱口令验证。
- 云端渗透测试。
- 自动攻击路径分析。
- 面向攻击者的高级搜索语法开放。
- 替代本地安全工具箱的扫描、巡检和处置能力。
- 多供应商结果完全一致性保证。

## 7. 功能需求

### 7.1 发现任务

- 支持创建、查看、取消和重试发现任务。
- 每个任务必须记录租户、操作者、创建时间、任务目的、输入种子和目标区域。
- 每个任务必须有状态：`created`、`queued`、`running`、`partial_success`、`success`、`failed`、`cancelled`。
- 每个任务必须记录调用的数据来源和结果数量。

### 7.2 查询输入

- 支持根域名，例如 `example.org`。
- 支持组织名，例如客户登记名称或常用英文名。
- 支持 IP 段，例如 `203.0.113.0/24`。
- 支持输入说明，用于记录任务目的和授权范围。
- 系统应提示用户只输入已授权组织资产。

### 7.3 查询规划

- 系统将用户输入转换为受控 FOFA 查询模板。
- 不允许 MVP 用户直接输入任意 FOFA 查询语法。
- 查询规划必须记录 `source_query`，用于审计和问题排查。
- 查询规划应预估配额消耗。

### 7.4 结果归一化

- 将不同来源字段归一化为统一资产、服务和风险线索模型。
- 保留来源、发现时间、原始引用、证据摘要和置信度。
- 对疑似同一资产进行去重合并。

### 7.5 风险线索

MVP 风险线索包括：

- 远程访问入口，例如 RDP、SSH、VPN、远程管理面板。
- 管理后台，例如后台登录页、控制台、管理端口。
- 疑似测试环境，例如标题或域名包含 test、dev、staging、uat。
- 高风险开放服务，例如数据库、缓存、中间件直接暴露。
- 疑似过期组件或异常服务，基于 banner、标题或组件字段判断。

风险线索只作为被动发现提示，不等同于漏洞确认。

## 8. 报告需求

管理者报告必须包含：

- 暴露面总览。
- 新发现资产数量。
- 高风险暴露服务数量。
- 开放端口分布。
- 疑似远程访问入口。
- 疑似管理后台。
- 疑似测试环境。
- 证书和域名暴露情况。
- 资产归属置信度。
- 优先处置建议。
- 技术附录资产清单。

报告语言要求：

- 先给结论，再给证据。
- 避免堆砌端口、banner 和原始字段。
- 对每个高风险建议说明“为什么重要”和“下一步怎么做”。
- 明确提示被动发现结果需要本地验证。

## 9. 权限与审计需求

- 只有授权用户可以创建发现任务。
- 管理者可以查看报告摘要。
- IT 管理员可以查看技术附录和来源证据。
- 系统管理员可以查看调用日志、配额消耗和失败原因。
- 审计日志必须记录操作者、租户、任务目的、输入摘要、数据来源、调用时间、结果数量和错误信息。
- 审计日志不得记录完整敏感密钥或未经脱敏的原始响应。

## 10. 成功指标

MVP 成功指标：

- 80% 以上试点客户可以在 10 分钟内完成首次任务创建。
- 90% 以上任务能给出成功、部分成功或明确失败原因。
- 管理者报告能在 3 页内说明主要风险和处置优先级。
- IT 管理员能从报告附录中导出可复核资产清单。
- FOFA 查询失败不影响已获得结果展示。
- 每个高风险线索都有来源和证据摘要。

## 11. 当前假设

- 第一版报告定位为管理者摘要优先。
- 技术资产清单作为附录，不作为首页主体。
- FOFA 是唯一必做数据源。
- 后续扫描、验证和整改都在客户本地安全工具箱完成。
