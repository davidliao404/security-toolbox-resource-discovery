# 互联网暴露面资源发现模块总体架构设计

## 1. 架构目标

架构目标是用最小可控的云端能力，把外部资产发现 SaaS 的被动情报安全地接入私有化“安全工具箱”，并输出管理者可读报告。

设计原则：

- 云上只做被动发现、聚合、归一化、短期快照、审计和报告辅助。
- 本地安全工具箱负责扫描、验证、巡检和整改。
- 所有外部 SaaS 通过连接器适配，避免供应商绑定。
- 每条结论保留来源、查询、证据和置信度。
- 双区域部署，区分香港区域和内地区域的合规与供应商配置。

## 2. 总体链路

```text
安全工具箱客户端
  -> 资源发现网关 API
    -> API 鉴权与租户隔离
    -> 任务管理器
    -> 查询规划器 Query Planner
    -> SaaS 连接器 Connector Adapters
      -> FOFA
      -> 后续候选：Shodan / Censys / ZoomEye / 360 Quake / 鹰图
    -> 结果归一化 Normalizer
    -> 去重与合并 Deduplicator
    -> 风险线索生成 Risk Hint Engine
    -> 报告生成 Report Builder
    -> 审计、配额和快照
  -> 返回安全工具箱
  -> 本地验证、巡检、整改和报告展示
```

## 3. 边界划分

### 3.1 私有化安全工具箱

负责：

- 用户登录与本地权限。
- 任务创建入口。
- 报告展示。
- 资产确认和标记。
- 本地扫描、漏洞验证、弱口令验证、基线巡检。
- 本地整改任务和闭环。

不负责：

- 保存外部 SaaS 平台密钥。
- 直接调用 FOFA 等外部 SaaS。
- 在第一版中实现多供应商字段适配。

### 3.2 公有云资源发现网关

负责：

- 接收安全工具箱请求。
- 租户鉴权和 API 签名校验。
- 查询规划。
- SaaS 连接器调用。
- 结果归一化、去重、置信度和风险线索。
- 短期快照和审计。
- 报告数据结构生成。

不负责：

- 主动扫描客户资产。
- 漏洞利用或验证。
- 直接执行整改。
- 永久保存完整客户资产库。

### 3.3 外部 SaaS

负责：

- 提供被动资产发现、互联网测绘或主机搜索数据。
- 返回资产、端口、服务、标题、证书、组件等信息。

不负责：

- 判断客户资产归属的最终结论。
- 承诺数据实时性。
- 替代本地验证。

## 4. 网关内部组件

### 4.1 Gateway API

提供安全工具箱调用入口：

- 创建发现任务。
- 查询任务状态。
- 拉取发现结果。
- 拉取报告数据。
- 取消或重试任务。

要求：

- 所有请求必须带租户标识、客户端标识、时间戳和签名。
- API 必须校验区域和租户权限。
- API 不接受任意外部 SaaS 原生查询语句。

### 4.2 任务管理器

负责：

- 任务状态流转。
- 任务排队和并发控制。
- 重试和超时控制。
- 快照写入。
- 任务级配额统计。

状态包括：

- `created`
- `queued`
- `running`
- `partial_success`
- `success`
- `failed`
- `cancelled`

### 4.3 查询规划器

负责把输入种子转换为受控查询计划：

- 根域名 -> 域名、子域名、证书主体相关查询。
- 组织名 -> 标题、证书组织、备案或主体相关查询。
- IP 段 -> IP 范围查询。

查询计划必须记录：

- `source`
- `source_query`
- 输入种子引用
- 预计配额消耗
- 查询目的

### 4.4 SaaS 连接器

每个连接器单独适配：

- 认证方式。
- 查询语法。
- 分页方式。
- 限速和重试。
- 错误码。
- 配额统计。
- 字段映射。

MVP 只实现 FOFA 连接器设计与 PoC。Shodan、Censys、ZoomEye 等只保留接口扩展位。

### 4.5 结果归一化

Normalizer 将不同来源结果转为统一模型：

- 资产。
- 暴露服务。
- 风险线索。
- 来源证据。
- 置信度。

不得丢弃原始来源信息。原始响应不应长期保存，必要时保存脱敏摘要和原始引用。

### 4.6 去重与合并

默认去重键：

```text
domain_or_ip + port + protocol + service
```

辅助合并依据：

- 证书指纹。
- 标题。
- banner hash。
- 同源 IP。
- 同一根域名。

合并后必须保留多个来源的证据，而不是只保留最后一个来源。

### 4.7 风险线索生成

Risk Hint Engine 基于规则生成被动风险线索：

- 远程访问入口。
- 管理后台。
- 测试环境。
- 数据库或中间件暴露。
- 疑似过期组件。
- 异常端口或异常标题。

风险线索不是漏洞结论，报告中必须说明需要本地验证。

### 4.8 报告生成

Report Builder 生成结构化报告数据：

- 管理者摘要。
- 暴露面指标。
- 关键风险。
- 优先处置建议。
- 技术附录。
- 来源和证据。

报告最终展示由安全工具箱完成，网关只返回报告数据结构和摘要文本。

## 5. 数据流

1. 安全工具箱提交任务种子和任务目的。
2. 网关鉴权并校验租户配额。
3. 任务管理器创建任务。
4. 查询规划器生成 FOFA 查询计划。
5. FOFA 连接器执行分页查询。
6. Normalizer 归一化结果。
7. Deduplicator 合并重复资产。
8. Risk Hint Engine 生成风险线索。
9. Report Builder 生成管理者报告结构。
10. 网关保存短期快照和审计日志。
11. 安全工具箱拉取结果并展示。

## 6. 双区域部署

### 6.1 香港区域

适用客户：

- 香港非盈利组织。
- 跨境敏感客户。
- 不希望任务数据进入内地区域的客户。

特点：

- 独立租户、密钥、日志和快照存储。
- 优先接入适合香港和国际资产发现的数据源。
- 明确供应商调用路径和数据处理说明。

### 6.2 内地区域

适用客户：

- 内地中小企业。
- 非核心政府单位。
- 对内地合规和国产供应商有要求的客户。

特点：

- 独立租户、密钥、日志和快照存储。
- 优先接入 FOFA、360 Quake、鹰图等更贴近内地场景的来源。
- 对数据出境和个人信息处理进行更严格默认限制。

### 6.3 区域隔离要求

- 区域间不共享 SaaS 密钥。
- 区域间不共享任务快照。
- 区域间不复制客户输入种子。
- 管理后台跨区域查看必须有单独授权和审计。

## 7. 高可用与扩展性

MVP 不追求复杂分布式架构，但必须预留：

- 任务队列。
- 连接器并发限制。
- 失败重试。
- 快照存储。
- 配额控制。
- 区域级配置。

后续扩展方向：

- 多供应商并行查询。
- 结果交叉验证。
- 历史趋势。
- 变更告警。
- 报告模板定制。

## 8. 失败降级策略

失败场景和处理：

- FOFA 认证失败：任务失败，提示供应商认证异常。
- FOFA 限速：任务进入部分成功或等待重试。
- 单页查询失败：保留已获得结果，记录失败页。
- 查询超时：返回部分结果和明确失败原因。
- 归一化失败：隔离异常记录，不影响其他结果。
- 报告生成失败：返回技术资产清单和错误信息。

报告中必须标注数据来源不完整的情况。

## 9. 当前假设

- MVP 只强制验证 FOFA。
- 安全工具箱通过 API 调用网关。
- 网关保存短期快照，不保存永久完整资产库。
- 双区域部署作为架构原则，PoC 可先选择一个区域实现。
